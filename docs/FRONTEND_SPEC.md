## 项目概述

### 背景

基于 Vue 3 + Phaser 3 重写的塔防游戏前端，负责游戏渲染、用户交互和数据记录。

### 核心问题

- 实现流畅的 60 FPS 游戏体验
- 精确记录游戏数据供服务端验证
- 支持 Mock 模式实现前后端并行开发

### 目标用户

- 休闲游戏玩家
- 支持桌面浏览器（Chrome、Firefox、Safari、Edge）

## 功能需求

### 核心功能（必须有）

**游戏核心**：

- 16x16 格子地图渲染
- 5 种防御塔建造、升级、出售
- 9 种怪物渲染和移动
- 子弹飞行和碰撞检测
- 动态寻路（BFS 算法）
- 波次管理和怪物生成

**用户交互**：

- 建筑选择面板
- 建筑放置（点击格子）
- 建筑升级/出售（选中后操作）
- 游戏暂停/继续
- 游戏结束弹窗和昵称输入

**数据同步**：

- 每波结束时提交数据到服务端
- 同步服务端状态（金钱、分数、生命）
- 接收下一波怪物配置

### 扩展功能（应该有）

- 排行榜查看
- 主题切换（明/暗）
- 多语言支持（中/英）
- 游戏速度调节

### 可选功能（可以有）

- 音效和背景音乐
- 建筑射程预览
- 怪物血条显示

## 用户界面规范

### 布局结构

```
┌─────────────────────────────────────────────┐
│  Header: 金钱 | 生命 | 分数 | 波次 | 设置  │
├─────────────────────────────────────────────┤
│                                             │
│                                             │
│              Game Canvas                    │
│              (512x512px)                    │
│                                             │
│                                             │
├─────────────────────────────────────────────┤
│  Building Panel: [墙][LMG][炮台][HMG][激光] │
└─────────────────────────────────────────────┘
```

### 游戏画布

- 尺寸：512x512 像素（16x16 格子，每格 32px）
- 入口标记：左上角 (0,0)，绿色
- 出口标记：右下角 (15,15)，红色
- 格子网格：浅色边框

### Header 信息栏

显示内容：

- 金钱：当前可用金币
- 生命：当前剩余生命（最大 100）
- 分数：累计得分
- 波次：当前波次号
- 设置按钮：主题、语言切换

### Building Panel 建筑面板

显示 5 种建筑选项：

- 显示：图标 + 名称 + 造价
- 状态：可购买（亮）/ 金钱不足（暗）
- 选中状态：高亮边框

选中建筑后显示：

- 升级按钮（显示升级费用）
- 出售按钮（显示回收金额）
- 当前等级

### 弹窗组件

**游戏结束弹窗**：

- 显示最终分数和完成波次
- 昵称输入框（1-32 字符）
- 提交按钮
- 提交后显示排名

**排行榜弹窗**：

- 排名列表（排名、昵称、分数、波次）
- 高亮当前玩家（如刚提交）

## 交互流程

### 游戏启动流程

```
页面加载
    │
    ├─ 调用 POST /sessions 创建会话
    │
    ├─ 接收 config + firstWave
    │
    ├─ 渲染地图、初始化状态
    │
    └─ 等待玩家放置第一个建筑
```

### 建筑放置流程

```
点击建筑面板选择建筑类型
    │
    ├─ 检查金钱是否足够
    │
    ├─ 点击地图格子
    │      │
    │      ├─ 检查格子是否可放置
    │      │      - 不是入口/出口
    │      │      - 没有已有建筑
    │      │      - 不会阻断路径
    │      │      - 不会困住怪物
    │      │
    │      ├─ 扣除金钱
    │      │
    │      ├─ 放置建筑
    │      │
    │      └─ 记录 BUILD 操作
    │
    └─ 如果是第一个建筑，开始游戏
```

### 波次进行流程

```
波次开始
    │
    ├─ 按间隔生成怪物（每 30 帧一个）
    │
    ├─ 每帧更新
    │      ├─ 怪物移动（寻路）
    │      ├─ 建筑寻找目标
    │      ├─ 发射子弹 / 激光命中
    │      ├─ 子弹飞行和碰撞检测
    │      └─ 记录攻击事件
    │
    ├─ 怪物死亡
    │      ├─ 记录击杀
    │      └─ 增加金钱
    │
    ├─ 怪物到达终点
    │      ├─ 记录穿过
    │      └─ 扣除生命
    │
    └─ 所有怪物处理完毕 → 波次结束
```

### 波次结束流程

```
波次结束
    │
    ├─ 设置波次持续帧数
    │
    ├─ 调用 POST /sessions/wave 提交数据
    │      ├─ actions: 建筑操作列表
    │      ├─ attacks: 攻击事件列表
    │      ├─ result: 战斗结果
    │      └─ buildings: 当前建筑列表
    │
    ├─ 接收响应
    │      ├─ serverState: 同步状态
    │      ├─ nextWave: 下一波配置
    │      └─ lifeReward: 生命奖励
    │
    ├─ 应用生命奖励（如有）
    │
    ├─ 等待波次间隔（180 帧）
    │
    └─ 开始下一波
```

### 游戏结束流程

```
生命值归零 或 玩家主动结束
    │
    ├─ 显示游戏结束弹窗
    │
    ├─ 玩家输入昵称
    │
    ├─ 调用 POST /sessions/end
    │      ├─ nickname: 玩家昵称
    │      └─ lastWave: 最后一波数据（如有）
    │
    ├─ 接收排名信息
    │
    └─ 显示排行榜
```

## 数据记录规范

### 记录时机

每个操作发生时立即记录，确保数据完整性。

**建筑操作**：

- BUILD：放置建筑时记录 type, buildingType, buildingId, position, frame
- UPGRADE：升级建筑时记录 type, buildingId, level, frame
- SELL：出售建筑时记录 type, buildingId, frame

**攻击事件**：

子弹命中或激光命中时记录：

```typescript
interface AttackEvent {
  frame: number                              // 命中帧号
  buildingId: string                         // 攻击建筑 ID
  originalTargetId: string                   // 发射时瞄准的怪物 ID
  originalTargetPosition: [number, number]   // 发射时目标位置
  monsterId: string                          // 实际命中的怪物 ID
  monsterPosition: [number, number]          // 命中时怪物位置
  damage: number                             // 实际伤害
}
```

**战斗统计**：

- 击杀时：killedByType[type]++, totalLifeDestroyed += monster.life
- 穿过时：passed++, lifeLost += monster.damage
- 每次命中：totalDamageDealt += damage, scoreGained += floor(sqrt(damage))

### 帧号规则

- 帧号从 0 开始，每帧递增 1
- 暂停时帧号不增长
- 所有时间相关记录使用帧号，不使用系统时间戳

### waveDurationFrames 计算

- 起点：波次第一个怪物生成的帧号
- 终点：波次最后一个怪物死亡或穿过的帧号
- 计算：endFrame - startFrame

## 边界条件与约束

### 输入限制

**昵称**：

- 长度：1-32 字符
- 不能为纯空白
- 允许中文、英文、数字

**建筑放置**：

- 不能放置在入口 (0,0) 或出口 (15,15)
- 不能放置在已有建筑的格子
- 不能完全阻断入口到出口的路径
- 不能使已存在的怪物无法到达出口

### 业务规则

**金钱约束**：

- 建造前检查金钱是否足够
- 升级前检查金钱是否足够
- 金钱不能为负

**生命约束**：

- 初始生命：100
- 最大生命：100
- 生命降为 0 时游戏结束

**怪物 ID**：

- 必须使用服务端下发的 UUID
- 不能自己生成怪物 ID

### 已知限制

- 仅支持单人游戏
- 不支持存档/读档
- 会话最长 24 小时，超时自动失效

## 验收标准

### 功能验收

**游戏核心**：

- 可以正常建造、升级、出售 5 种建筑
- 怪物按正确路径移动
- 建筑可以攻击射程内的怪物
- 子弹有飞行轨迹，可命中移动中的怪物
- 波次正常切换，难度递增

**数据提交**：

- 每波结束时成功提交数据
- 服务端状态正确同步
- 游戏结束时成功提交并获取排名

**UI 交互**：

- 建筑面板正确显示可购买状态
- 选中建筑时显示升级/出售选项
- 游戏结束弹窗正常显示和输入

### 测试场景

- 正常通关：完成 10+ 波次并提交成绩
- 快速失败：第 1 波不建造建筑，验证生命扣除
- 提前结束：波次进行中结束游戏
- 会话过期：模拟 SESSION_NOT_FOUND 错误处理
- Mock 模式：无后端情况下完整游戏流程

### 性能指标

- 帧率：稳定 60 FPS
- 首屏加载：< 3 秒
- API 响应处理：< 1 秒
